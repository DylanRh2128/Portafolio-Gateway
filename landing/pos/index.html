QuickBite POS — Restaurant Billing System

A desktop point-of-sale built for a real fast-food restaurant (shown here with its brand removed). It replaced a system whose credentials had left with former staff, and it works offline: billing can't stop because the internet did. Designed so a new cashier can take an order without training — a visual menu instead of codes.

.NET 8 · Blazor Hybrid (WPF + BlazorWebView) · Entity Framework Core · PostgreSQL · xUnit · GitHub Actions
Source on GitHub (portfolio version) Open the prototype full screen
What it does
  • Visual menu with photos, search by name or price, add-ons per product.
  • Dine-in, take-away and delivery orders in a single screen.
  • Delivery cost computed from the customer's street, using zones the admin configures (with overlap warnings).
  • Recurring customers found by name or phone, address filled in.
  • Change calculator for cash, or a pasted transfer receipt (Ctrl+V).
  • Cash-register close-out by operating day — shifts that cross midnight still count as one day.
  • Sales reports by day, month and year; close-out history for month end.
  • Thermal printer tickets; cashier and administrator roles.
Architecture
Facturacion.Desktop — WPF window hosting BlazorWebView, the .exe and DI setup
Facturacion.UI — Razor screens and shared components, no business logic
Facturacion.Core — pure business rules (delivery zones, change, operating day), no UI or SQL
Facturacion.Data — EF Core + PostgreSQL repositories implementing Core's interfaces

Dependencies only point down, so the rules most likely to cost money — delivery pricing, change, close-out — are unit-tested in isolation with in-memory fakes, and run in CI on every push.
